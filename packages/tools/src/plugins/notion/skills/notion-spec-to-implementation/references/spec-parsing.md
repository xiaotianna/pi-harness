# Parse the specification

Retrieve the supplied spec or search title terms using the access guide. Read relevant nested blocks and linked requirements. Capture source URL and section for each extracted requirement.

Separate goals, functional requirements, nonfunctional constraints, acceptance criteria, dependencies, exclusions, priorities and open questions. Preserve explicit must/should distinctions. Identify conflicting statements and undocumented assumptions before translating them into implementation decisions.

Create a compact requirement-to-task mapping: requirement, evidence link, intended behavior, acceptance check and dependent task. A possible solution mentioned in discussion is not automatically an approved requirement. Ask only for uncertainty that materially blocks the requested implementation; continue independent work where possible.

Keep estimates and owners unspecified unless supplied or requested as estimates. Validate that the plan covers every required behavior and that no task expands the agreed scope.
