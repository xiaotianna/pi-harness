# Task drafts

Discover the intended task database through title search and fetch its actual data-source schema using the access guide. Use returned UUIDs and property options. If the destination is unknown, draft tasks locally first and mark the destination unresolved.

Each task should describe one reviewable outcome: title/action, context and source spec, intended behavior, acceptance checks, dependencies and known owner/priority. Split work by coherent deliverables rather than imposing an arbitrary duration. Preserve the plan/spec links and avoid fabricated remote page IDs.

Draft the Markdown task body using task-creation-template.md and include proposed properties separately. Reuse an existing matching task when updating work; show the exact proposed changes based on its current content. A dependency must refer to a real existing task or a clearly labeled local draft identifier.

The current gateway cannot create tasks or update properties. Deliver the complete local task set and its intended destination; publishing requires a separate available write integration. No Notion status changes occur merely because code was edited locally.
