# Database schema and draft properties

Inspect the existing database/data-source schema through the access guide before drafting records. Preserve property names and types. A title, text field, relation, people field, date and status have different meanings; do not infer person IDs or relation targets from a display label alone.

Choose an existing knowledge destination when it fits. Propose a new database only when requested or required by the stated workflow. Draft its schema with title, type, purpose and allowed options, but do not claim it was created. Prefer a small set of useful properties to a template's entire catalog.

Avoid duplicate records by checking existing titles and linked source pages. For changes prepare the current value, proposed value and rationale. Keep source links and identify required properties with missing values. Notion formula/rollup/system properties are derived; do not propose ordinary writes to them.

Deliver a Markdown body and explicit proposed properties for the chosen destination. All templates are conceptual and must be reconciled with the fetched schema; the access guide defines the actual available operations.
