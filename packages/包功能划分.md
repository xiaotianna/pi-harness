# Packages 功能划分

| Package | 职责 | 不负责 |
|---|---|---|
| `agent-runtime` | Agent 创建与恢复、run 编排、Pi 事件适配、Context 和 HITL 挂起/恢复 | HTTP、SSE、SQL、文件或 Shell 实现 |
| `providers` | 创建 `pi-ai Models`、按需加载内置 Provider，并原样导出自定义 Provider 所需的 `pi-ai` 能力 | HTTP、配置校验、凭据与 SQLite 持久化、Web 状态、自研模型协议客户端 |
| `tools` | package 根目录负责 Tool/Skill Registry、选择与执行保护；`tools/` 和 `skills/` 分别保存具体 Tool 与 Skill 定义 | 用户审批、SSE、数据库事务 |
| `computer-use` | macOS Computer Use 协议与 Agent Tool；管理 Rust helper，以单帧窗口截图、Accessibility Tree 和输入事件形成观察/动作闭环 | 审批决策、UI、视频流、Session 持久化 |
| `policy` | Tool/Skill 权限、路径与命令策略、审批等待 | 工具执行和 UI |
| `sandbox` | Shell 与 stdio MCP 的 SRT 隔离、远程 MCP 网络边界 | 权限决策、Agent 编排 |

Memory、Retrieval 和 Trace 初期留在 daemon 或实际消费模块内。只有出现第二个真实运行时消费者时，才提取为 workspace package。

Human-in-the-loop 不单独拆 package：daemon 的 `HumanInteractionService` 负责持久化、SSE 和用户回复，`agent-runtime` 负责挂起/恢复，`policy` 负责安全审批决策。

Provider 配置由 daemon 的 `ProviderService` 和 `ProviderRepository` 管理，CredentialStore 也由 daemon 持久化；`packages/providers` 不执行校验、文件读写或 SQL。运行时注册和查询直接复用 `pi-ai Models`，不创建重复的 Provider Registry 或 Model Registry 类。自定义 Provider 第一版只使用 `pi-ai` 已有的 OpenAI Completions、OpenAI Responses 和 Anthropic Messages 协议实现。

MCP Client + Host 为待实现目标，任务状态统一见 [MCP 实施台账](../docs/mcp-client-host-plan.md)。官方 Client SDK、连接生命周期、认证和持久化留在 daemon；tools 提供工具适配及执行接口，daemon 注入实现；agent-runtime 负责 Run 前工具快照与现有事件链，policy 负责外部调用授权。Web 只使用项目 API；不为单一消费者预建 MCP Host/Client package，也不提供对外 MCP Server。
