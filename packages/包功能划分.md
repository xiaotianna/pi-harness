# Packages 功能划分

| Package | 当前职责 | 实现边界 |
|---|---|---|
| `agent-runtime` | Agent 创建/恢复、Run 编排、父子执行树、Pi 事件适配、Context/压缩/checkpoint、Plan/工作状态、HITL 挂起恢复 | SQL、HTTP/SSE 和具体文件/Shell 执行由 daemon/tools 提供，通过回调及运行端口接入 |
| `providers` | 创建 pi-ai Models、按需加载内置 Provider，导出自定义 Provider 所需 pi-ai 能力 | 配置校验、凭据和持久化在 daemon；注册与模型协议复用 pi-ai |
| `tools` | Tool/Skill Registry、执行保护、文件/文档/PDF/网络/Shell 工具、命令进程管理、规划/人工输入/Sub Agent 控制工具、Skill/插件发现、MCP 工具混合检索与按需加载 | 审批决策交给 policy/runtime；MCP Client/Credential Store 在 daemon，通过回调上报事件 |
| `memory` | 浏览器安全 contract、领域校验、去重/revision 冲突规则、用户画像派生、混合召回、Context 投影与 Agent 工具 | 定义 repository/embedder 端口；SQLite、模型推理、HTTP/运行时装配在 daemon |
| `computer-use` | macOS 观察/动作协议、Agent 工具、受限 JavaScript、helper 客户端；Rust 原生 MCP、窗口截图、Accessibility Tree、输入和 Swift overlay | daemon 管理 MCP、系统权限与应用授权；运行记录走 Session 事件链 |
| `policy` | 路径、命令、外部连接、Tool 权限、Sandbox Profile/网络规则，以及稳定审批策略与结果 contract | 工具执行在 tools/sandbox；审批等待与用户回复由 daemon 人工交互服务和 Runtime 完成 |
| `sandbox` | Shell/第三方 stdio MCP 的 SRT 进程隔离、Profile 和远端网络边界 | 授权由 policy/runtime 决定；需要 macOS TCC 的签名内置 helper 使用独立权限链 |
| `evals` | Context 确定性场景、JSONL 写入/回退/重启恢复、显式真实 Provider 压缩评估 | 开发评估包，通过 daemon 的 session-event-store 公开子路径复用真实 JSONL adapter，不参与产品装配 |

`hero-ui-pro/` 也是 workspace 成员，以 `@agile-avocation/ui-pro` 导出兼容组件与 CSS 产物供 Web 消费。它是 UI 依赖，不承担 Agent、daemon 或领域编排。

## 跨层边界

Web 使用 `agent-runtime`、`policy` 的浏览器安全子路径获取事件、用户输入、推理档位、模型偏好、工作状态、审批和 Sandbox contract，以及 `memory/contract`。Web 不导入这些包的 Node Runtime 入口、tools、Provider、MCP SDK 或 daemon storage。package exports 是可用入口清单，跨层消费由原所有者提供最小公开导出，不在消费者复制协议。

daemon 是组装根，负责 HTTP/SSE、Auth、Workspace、Session、BoardTask、Provider/MCP/插件连接、文件打开、Computer Use 权限，以及当前唯一的 SQLite/JSONL/Credential Store 实现。Tauri 管理窗口、本地端口、Node sidecar 与外部授权 URL；业务仍走 daemon HTTP API。

Human-in-the-loop 没有单独 package：`HumanInteractionService` 管理等待与用户回复，Runtime 发出并收束关联事件、挂起与恢复，policy 负责安全决策。Sub Agent 分布在 Runtime 执行树、tools 控制工具、daemon API 和 Web 投影，也没有独立子 Agent 持久化包。

## 检索、Provider 与 MCP

Memory 因 daemon、Runtime 和 Web 的真实跨层消费独立成包。SQLite adapter 与本地 `multilingual-e5-small` embedding 位于 daemon；用户画像由记忆派生，不是第二事实源。

MCP 工具检索由 tools 的 `HybridToolSearch` 完成，支持精确名称优先与 BM25/本地向量融合；daemon 将同一本地 embedder 注入 Runtime。主 Agent 与 worker 子 Agent 的 `tool_search` 默认自动加载 8 个匹配定义，单次最多 10 个，下一次模型请求才提供完整 schema，执行继续经过 Policy/审批。Memory、MCP 工具和 Session 历史各自保留检索路径，当前没有通用 RAG/Retrieval package。

Provider 配置由 daemon `ProviderService` 和 `ProviderSettingRepository` 管理，独立 `FileCredentialStore` 保存密钥/OAuth；providers 复用 pi-ai Models。自定义 Provider 使用已有 OpenAI Completions、OpenAI Responses 和 Anthropic Messages 协议，不自研模型客户端。

MCP 官方 Client SDK、transport、目录、OAuth 和 Credential Store 留在 daemon；tools 提供受保护注册/执行契约，`McpToolService` 注入调用实现；Runtime 固定 Run 目录并管理按需工具快照。产品作为 MCP Host，不提供对外 MCP Server。Computer Use helper 的 MCP 是内置插件专用执行端，不改变产品 Host 边界。

Trace 由 Web 从 `HarnessEvent` 派生，完整事实在 daemon JSONL；没有独立 observability package、daemon observability 目录或统一 span 输出层。详细边界见 [架构设计](../docs/架构设计.md)。
