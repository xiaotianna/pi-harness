# MCP 连接与使用

当前已接通 MCP 配置、连接信任、能力发现、工具检索与按需加载、审批、执行和设置界面。

## 在哪里连接

1. 登录 PI Harness，打开侧栏的设置，选择 **MCP 服务器**。
2. 点击 **添加服务器**，通过 Tab 选择 **表单配置** 或 **JSON 配置**。两种视图编辑同一份服务器配置，并共用私网访问和调用超时设置；编辑已有服务器时也可随时切换。连接方式支持 Streamable HTTP、stdio 和 SSE。远程服务默认使用“自动检测”，静态鉴权 Header 直接随连接配置填写。
3. JSON 示例：

   ```json
   {
     "mcpServers": {
       "basil": {
         "url": "https://example.com/api/mcp",
         "headers": {
           "Authorization": "Bearer <token>"
         }
       }
     }
   }
   ```

   `mcpServers` 下的每个 key 都是服务器 ID；表单中的「服务器 ID」与该 key 是同一字段。

4. HTTP 填写完整 MCP endpoint，并在「自定义 Headers」中按行添加名称和值；**沙箱 → 联网规则 → 允许访问** 非空时，需要允许 endpoint 及 OAuth 可能访问的域名，留空则允许所有未被拒绝的目标。本机/局域网地址还需要在表单中明确打开对应选项；查询参数、URL 内嵌账号密码目前不支持。本地命令使用 `command`，命令参数每行填写一项，环境变量每行使用 `KEY=VALUE`。
5. 保存配置并先开启服务器。首次连接收到 401 后，列表和详情会显示“需要 OAuth 授权”或“需要 Token / API Key”：OAuth 通过独立小窗口完成，静态凭据回到连接配置中填写 Header。OAuth 入口只在服务器已开启后可用，授权完成后保持开启。JSON 使用常见的 `mcpServers` 结构；Streamable HTTP 可省略 `type`，SSE 使用 `sse`，stdio 使用 `stdio` 并支持字符串数组 `args` 和字符串对象 `env`。`headers` 和 `env` 从连接配置接收后写入 daemon Credential Store，不进入 SQLite 或浏览器持久化；打开编辑弹窗时通过禁止缓存的专用接口按需读取并回填，关闭弹窗后不进入共享查询缓存。OAuth Token 不回显。stdio 使用可执行文件和独立参数数组，不将 `command` 当作 Shell 命令解析；推荐填写可执行文件的绝对路径，裸命令只从 daemon 固定的程序目录查找，不从 workspace 或任意 `PATH` 查找。
6. 使用服务器条目尾部的开关启用连接。首次启用时审阅服务器地址或完整命令，再点击 **信任并测试连接**。配置由所有项目共用，无需选择或绑定项目。
7. daemon 启动后会直接复用已启用且受信任服务器的有效本地能力目录，只在缓存缺失、配置版本不匹配或损坏时后台补齐；新增单台服务器完成信任、服务器从关闭切换到开启、或点击详情中的「刷新状态」时，也会立即刷新并保存该服务器。详情直接读取本地保存的工具、资源、提示词与服务信息；连接期间显示 loading。加载后可逐个停用工具，或把确认过的只读工具标记为「可信只读（免审批）」。消息输入器的“+ → MCP”只插入服务提示标签，不改变启用范围或审批边界。

JSON 是用户侧导入/导出的标准形态；daemon 会在 API 边界补齐安全默认值并把非敏感运行配置标准化保存到 SQLite，不会在工作区写入可被 Agent 修改的 `mcp.json` 文件。

设置内容来自当前运行的 Web 和 daemon。如果更新源码后仍找不到入口或出现响应格式错误，请确认两个进程都已加载最新代码。

## 插件 App 与 Skill

「设置 → 插件」中的内置插件可以同时提供 App（MCP 服务）和 Skill。安装插件会建立它声明的 App 配置，App 需要单独开启；Skill 也有独立开关。首次开启 App 时 daemon 会保存连接信任并发现能力目录，将结果持久化到本地 SQLite，后续 daemon 重启直接复用有效目录；实际工具调用仍进入下述审批链。仅开启 Skill 不会开启 App，仅开启 App 也不会自动加载 Skill 正文。插件 App 详情复用 MCP 的目录、刷新和工具级设置；卸载插件会删除对应 App 服务器及插件凭据。

Computer Use 插件提供本机原生 MCP App 和操作 Skill。它要求 macOS 原生 helper 及系统权限，使用方式和隔离边界见 [Computer Use 说明](../packages/computer-use/README.md)。

连接采用标准 `initialize → notifications/initialized` 握手，使用 SDK 默认的 2025 系列协议协商。当前连接范围不包含仅支持 2026 `server/discover` 现代协议的服务器。已保存的自定义 Header 自动用于同源连接与工具请求。

## 授权与状态

- 保存配置不会启动服务器。连接信任与工具调用批准是两个独立动作。
- 服务器配置、凭据、信任和启用状态均为全局设置。关闭服务器开关或「撤销信任」会使所有会话中的该服务器连接失效。
- 开启服务器会执行连接与能力发现。连接失败且没有当前配置版本的有效目录时，daemon 会保存关闭状态；修正配置后可再次开启。已有有效目录的服务器刷新失败时，保留启用和缓存。连接与刷新操作的错误通过 Toast 提示，列表和详情的开关旁只保留操作控件；详情能力区域继续提供失败原因和缓存说明。等待补充凭据或 OAuth 授权时保留启用以完成授权；已保存请求头被拒绝且没有有效目录时仍会关闭。
- 支持 HTTP Bearer、API Key、自定义请求头、stdio 环境变量，以及 MCP OAuth discovery、动态客户端注册、PKCE、回调换 token 和 refresh。OAuth 临时回调状态只保留在 daemon 内存中，超过 10 分钟或 daemon 重启后需重新发起。
- 普通 stdio 服务在非完全访问模式下由独立 SRT worker 启动，遵循沙箱 Profile、联网规则、daemon 私有目录保护和进程组回收；完全访问下直接以宿主机权限启动。内置 Computer Use App 是原生宿主机 helper，所有模式都由 macOS 系统权限、应用授权和工具审批约束；它的 `computer_exec` JavaScript 子进程才在非完全访问模式下使用 SRT。Windows 长驻沙箱进程回收尚未验证，因此非完全访问模式下拒绝启动普通 stdio 服务。
- HTTP、SSE 普通审批模式下经过沙箱允许/拒绝域名规则，完全访问下跳过该规则；OAuth 仍使用联网规则。DNS 固定、私网和凭据目标检查保持生效。远端服务器自身的文件系统无法由本机 SRT 限制；工具执行仍遵循全局审批策略及调用前复查。
- 「请求批准」下，未分类且未获得有效授权的 MCP 工具逐次询问；「帮我批准」下由独立 AI 复核，只有明确判定为低风险才自动执行，否则询问；「完全访问权限」下自动批准工具调用。连接信任、OAuth/Token、macOS 系统权限与 Plan 确认仍是独立边界。人工审批卡可把同一 workspace、账号、配置、工具定义和精确参数组合持久授权；工具设置或任一范围变化后自动失效。用户明确标记的「可信只读」工具免工具审批，并可在未确认 Plan 中使用；服务端的只读 annotation 不会自动获得这个权限。Computer Use 工具禁止设置为可信只读，使用独立的应用观察授权和脚本审批。
- 每轮运行开始时从 SQLite 中按配置版本读取并固定工具目录，不再连接服务器或重新发现目录；MCP 工具默认不进入模型上下文。`tool_search({ query, limit? })` 综合服务名、原始工具名、能力描述和参数名称/描述的 BM25 排序与本地多语言向量检索，完整名称精确命中时优先并跳过向量计算；向量不可用或超时时退回 BM25 结果。中英文查询与工具元数据使用同一分词规则。搜索默认自动加载前 8 个匹配工具，`limit` 可指定 1 到 10 个，并按当前 Run 的剩余工具名额截断；结果列出已加载工具，完整定义进入下一次模型请求，后续可直接调用。主 Agent 与 worker 子 Agent 各自维护加载状态，搜索和加载不授予执行权限。新增或刷新后的目录在下一轮生效。撤销、停用或修改配置会即时使旧调用失效，真正执行工具时才建立或复用对应 Session Client。
- 远端服务在配置不变时新增或修改工具，需要在详情中点击「刷新状态」更新本地目录；重启不会主动重抓已有有效目录。
- 「测试通过」表示最近一次目录测试成功，不保证每个会话此刻已连接。测试不依赖项目，使用独立临时目录，结束即回收连接与目录。会话按需建立各自的 Client，使用该会话固定的工作目录；没有租约的已连接 Client 不按空闲时间关闭，只有达到 32 Client 上限、配置失效或 daemon 关闭时回收。
- 取消连接测试不会撤销已经保存的配置或授权；需要停止后续使用时，选择停用或撤销信任。

## 错误与限制

| 情况 | 处理方式 |
|---|---|
| 配置版本冲突 | 刷新状态后重试，避免覆盖其他窗口的修改 |
| 需要 OAuth 授权 | 先开启服务器，再点击 OAuth 授权并在独立窗口完成登录 |
| 需要 Token / API Key | 编辑连接配置，按服务文档填写请求头或环境变量，再重新信任 |
| 已配置请求头仍返回 401 | 提示“认证失败（HTTP 401）：已保存认证请求头，但服务拒绝认证”，并指引核对 Token/API Key、有效期、权限和请求头格式；保留已保存的普通静态凭据 |
| 启动或手动刷新目录失败 | 有有效缓存时保留启用与缓存；没有有效目录时关闭服务器。手动操作的错误通过 Toast 提示，详情能力区域保留原因。检查命令、HTTP endpoint、服务状态与私网访问选项后，再次开启或刷新 |
| 服务器工具定义无法准备 | 当前 Turn 以 MCP 工具失败状态显示原因并跳过该服务器；先在设置中刷新状态，再检查工具 schema、定义大小和全局启用的服务器数量 |
| 工具定义变化 | 结束当前轮后重新发起一轮，取得新的工具快照 |
| 执行结果未知 | 连接中断、超时或返回校验失败不代表操作没有发生；先核实外部数据，再决定是否发起新调用 |

当前每轮最多向模型暴露 64 个工具（包含内置工具和已加载的 MCP 工具），`tool_search` 默认加载 8 个匹配工具，单次最多 10 个，达到 64 个可见工具时不再加载。单台服务器的工具、资源、资源模板和提示词各自最多 512 项，整体能力目录最多 2 MiB；单个工具 schema 最多 128 KiB、2,048 个节点和 24 层深度，递归/外部引用和超出安全范围的正则会被拒绝。能力目录作为可重建派生数据保存在 SQLite，配置版本不匹配时不会复用；工具首次实际执行时按 Session 建立连接，此后复用连接。

工具文本、内嵌文本资源与结构化结果合计最多保留 64,000 字符，并移除已知连接凭据的原值；详情中的服务信息和完整目录定义同样会递归脱敏。图片已作为 `ImageContent` 保留，单个图片 base64 字符串最多 20,000,000 字符，超限时返回提示；音频和二进制资源仍显示未展开提示，资源链接仅作为引用返回，不自动读取。详情展示资源、资源模板和提示词定义，独立资源/模板读取、提示词调用、Completion、Elicitation、Sampling 和 MCP Tasks 尚未接入可用的产品流程。OAuth 远端注销、Windows 长驻隔离及完整崩溃恢复仍是后续能力。工具超时、断线或结果校验失败时不会自动重试，避免重复外部副作用。

已有配置通过 015 migration 自动升级：只移除旧的项目绑定表，保留服务器、启用状态、信任与凭据；016 migration 增加能力目录缓存。已有启用且受信任的服务器升级后供全部项目使用，并在 daemon 启动后后台写入首份目录快照。
