# MCP 连接与使用

当前已提供 MCP 工具的基础闭环；完整任务进度见 [实施台账](./mcp-client-host-plan.md)。

## 在哪里连接

1. 登录 PI Harness，打开侧栏的设置，选择 **MCP 服务器**。
2. 点击 **添加服务器**，通过 Tab 选择 **表单配置** 或 **JSON 配置**。两种视图编辑同一份服务器配置，并共用鉴权方式、私网访问和调用超时设置；编辑已有服务器时也可随时切换。连接方式支持 Streamable HTTP、stdio 和 SSE。远程服务默认使用“自动检测”。
3. JSON 示例：

   ```json
   {
     "mcpServers": {
       "time": {
         "type": "http",
         "url": "https://example.com/mcp"
       }
     }
   }
   ```

   `mcpServers` 下的每个 key 都是服务器 ID；表单中的「服务器 ID」与该 key 是同一字段。

4. HTTP 填写完整 MCP endpoint；**沙箱 → 联网规则 → 允许访问** 非空时，需要允许 endpoint 及 OAuth 可能访问的域名，留空则允许所有未被拒绝的目标。本机/局域网地址还需要在表单中明确打开对应选项；查询参数、URL 内嵌账号密码目前不支持。本地命令使用 `command`，命令参数每行填写一项，环境变量每行使用 `KEY=VALUE`。
5. 保存配置并先开启服务器。首次连接收到 401 后，列表和详情会显示“需要 OAuth 授权”或“需要 Token / API Key”：OAuth 通过独立小窗口完成，静态凭据通过「设置凭据」录入。OAuth 入口只在服务器已开启后可用，授权完成后保持开启。JSON 使用常见的 `mcpServers` 结构，`type` 使用 `http`、`stdio` 或 `sse`；stdio 支持字符串数组 `args` 和字符串对象 `env`。`env` 和远程凭据都只写入 daemon Credential Store，不进入普通配置、页面回显或浏览器持久存储。
6. 使用服务器条目尾部的开关启用连接。首次启用时审阅服务器地址或完整命令，再点击 **信任并测试连接**。配置由所有项目共用，无需选择或绑定项目。
7. daemon 启动后会在后台刷新已启用且受信任服务器的能力目录；新增单台服务器完成信任、服务器从关闭切换到开启、或点击详情中的「刷新状态」时，也会立即刷新并保存该服务器。详情直接读取本地保存的工具、资源、提示词与服务信息；连接期间显示 loading。加载后可逐个停用工具，或把确认过的只读工具标记为「可信只读（免审批）」。消息输入器的“+ → MCP”只插入服务提示标签，不改变启用范围或审批边界。

JSON 是用户侧导入/导出的标准形态；daemon 会在 API 边界补齐安全默认值并把非敏感运行配置标准化保存到 SQLite，不会在工作区写入可被 Agent 修改的 `mcp.json` 文件。

设置内容来自当前运行的 Web 和 daemon。如果更新源码后仍找不到入口或出现响应格式错误，请确认两个进程都已加载最新代码。本次实现未自动重启或启动开发服务。

## 授权与状态

- 保存配置不会启动服务器。连接信任与工具调用批准是两个独立动作。
- 服务器配置、凭据、信任和启用状态均为全局设置。关闭服务器开关或「撤销信任」会使所有会话中的该服务器连接失效。
- 支持 HTTP Bearer、API Key、自定义请求头、stdio 环境变量，以及 MCP OAuth discovery、动态客户端注册、PKCE、回调换 token 和 refresh。OAuth 临时回调状态只保留在 daemon 内存中，超过 10 分钟或 daemon 重启后需重新发起。
- stdio 服务在 POSIX 上统一由独立 SRT worker 启动，遵循沙箱 Profile、联网规则、daemon 私有目录保护和进程组回收，不提供直接启动旁路。Windows 长驻沙箱进程回收尚未验收，因此明确拒绝启动。
- HTTP、SSE 和 OAuth 每次请求都经过沙箱允许/拒绝域名、DNS 固定、私网和凭据目标检查。远端服务器自身的文件系统无法由本机 SRT 限制，其工具仍须逐次审批。
- 三种本地审批策略，包括「完全访问」，都不会自动批准未分类的外部 MCP 工具。审批卡可把同一 workspace、账号、配置、工具定义和精确参数组合持久授权；工具设置或任一范围变化后自动失效。只有用户明确标记的「可信只读」工具可免审批，并可在未确认 Plan 中使用。
- 每轮运行开始时从 SQLite 中按配置版本读取并固定工具清单，不再连接服务器或重新发现目录；新增或刷新后的目录在下一轮生效。撤销、停用或修改配置会即时使旧调用失效，真正执行工具时才建立或复用对应 Session Client。
- 「测试通过」表示最近一次目录测试成功。测试不依赖项目，使用独立临时目录，结束即回收连接与目录。会话按需建立各自的 Client，使用该会话固定的工作目录；空闲连接会被回收。
- 取消连接测试不会撤销已经保存的配置或授权；需要停止后续使用时，选择停用或撤销信任。

## 错误与限制

| 情况 | 处理方式 |
|---|---|
| 配置版本冲突 | 刷新状态后重试，避免覆盖其他窗口的修改 |
| 需要 OAuth 授权 | 先开启服务器，再点击 OAuth 授权并在独立窗口完成登录 |
| 需要 Token / API Key | 按服务文档设置请求头或环境变量凭据，再重新信任 |
| 启动或手动刷新目录失败 | 设置页显示加载失败并保留上一次同配置版本的本地快照；检查命令、HTTP endpoint、服务状态与私网访问选项后再次刷新 |
| 服务器工具定义无法准备 | 当前 Turn 以 MCP 工具失败状态显示原因并跳过该服务器；先在设置中刷新状态，再检查工具 schema、定义大小和全局启用的服务器数量 |
| 工具定义变化 | 结束当前轮后重新发起一轮，取得新的工具快照 |
| 执行结果未知 | 连接中断、超时或返回校验失败不代表操作没有发生；先核实外部数据，再决定是否发起新调用 |

当前每轮最多装配 64 个已启用 MCP 工具，工具定义合计不超过 512 KiB；复杂递归、外部 schema 引用和超出安全范围的正则会拒绝。能力目录作为可重建派生数据保存在 SQLite，配置版本不匹配时不会复用；工具首次实际执行时按 Session 建立连接，此后复用连接，空闲连接只在达到 32 Client 上限时回收。

工具文本与结构化结果有界输出，并移除已知连接凭据的原值；详情中的服务信息和完整目录定义同样会递归脱敏。图片、音频和二进制资源当前显示未展开提示，资源链接仅作为引用返回，不自动读取。详情展示资源、资源模板和提示词定义，但读取资源、填写提示词等交互仍未接入。OAuth 远端注销、Completion、Elicitation、Sampling、Windows 长驻隔离、资源上限矩阵及完整崩溃恢复仍在实施中。

已有配置通过 015 migration 自动升级：只移除旧的项目绑定表，保留服务器、启用状态、信任与凭据；016 migration 增加能力目录缓存。已有启用且受信任的服务器升级后供全部项目使用，并在 daemon 启动后后台写入首份目录快照。

本阶段已验证临时数据库升级、模拟 MCP 服务及实际 Agent Loop；已在登录后的浏览器检查全局入口、添加弹窗、连接方式切换、开关键盘操作与必填校验。真实第三方服务和完整生产矩阵尚未验收。
