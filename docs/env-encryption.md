# .env 加密备份

实现见 [env-crypt.mjs](../scripts/env-crypt.mjs)。

脚本只备份仓库根 `.env`，不改变 daemon 环境加载，也不备份运行数据目录中的 Provider、MCP 或插件 Credential Store。

## 创建与更新备份

在仓库根目录按需执行：

```sh
pnpm env:encrypt
```

首次加密且没有既有 `.env.enc` 时，脚本创建随机 256 位密钥 `.env.key`，以 64 个十六进制字符保存，文件权限为 `0600`。后续加密复用密钥，每次生成新的 12 字节 nonce。

格式为 `PIENV1` header、nonce、16 字节认证标签和 AES-256-GCM 密文；header 也参与认证。写入前先验证可完整还原，再将 `0600` 临时文件原子替换为 `.env.enc`。已有密文却缺少密钥时，加密直接失败，避免用新密钥覆盖无法还原的备份。

修改 `.env` 后再次加密即可更新 `.env.enc`。密文可随代码保存，密钥应单独备份到密码管理器；拥有二者即可读取全部配置，丢失密钥则无法恢复。

## 在另一台机器恢复

1. 将备份的 `.env.key` 放回仓库根目录，与 `.env.enc` 同级。
2. 保持根 `.env` 不存在；已有配置时先保存并移走，不直接覆盖。
3. 执行下列任一入口：

```sh
pnpm env:decrypt
```

尚未安装依赖时可直接运行：

```sh
node scripts/env-crypt.mjs decrypt
```

脚本先验证格式和 GCM 认证，再以独占创建方式写入 `0600` 的 `.env`。错误密钥、篡改、无效格式或已有 `.env` 都会失败；失败不会写出未经认证的明文。

## 文件管理与自检

当前 [.gitignore](../.gitignore) 忽略 `.env` 和 `.env.enc.*.tmp`，**没有列出 `.env.key`**。不要将该密钥加入版本控制；加密不等于密钥已经被忽略。脚本不会修改忽略规则，也不会执行 Git。

按需运行：

```sh
pnpm env:check
```

自检使用随机密钥与固定示例文本，覆盖普通/空文本往返、错误密钥、逐字节篡改和截断格式；不读取真实 `.env`、`.env.key` 或 `.env.enc`。

若密钥或明文曾经泄露，加密新备份不能撤回旧配置，应在对应服务中更换凭据。
